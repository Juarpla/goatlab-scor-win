# AdSense approval review for Labormin and GoatLab

November 7, 2026

## What the rejection tells us

Google uses “Your AdSense account wasn't approved” for multiple onboarding failures. Its help article lists duplicate publisher accounts and site content problems under that same heading. Initial account setup also includes checking payment information and reviewing the entire submitted site. A generic email and a resubmit prompt establish that onboarding did not finish. They leave the affected domain and cause unresolved. The strongest diagnostic evidence is a reason on the signed-in Home or Sites card, an explicit account task, or a more specific message from Google. [Account disapproval](https://support.google.com/adsense/answer/81904?hl=en), [Account setup](https://support.google.com/adsense/answer/7402256?linkId=17443183)

It gave no affected domain, violation code, example URL or duplicate-account identifier.
- Labormin's October 26 records show a review request and a “Getting ready” site state, with ads.txt marked “Not found” despite a successful public fetch. That establishes that Labormin was in the review flow before the October 30 notice. Its current approval and ads.txt states could not be read from the visible onboarding UI. [October 26 Labormin live check](<../../labormin-bitsamurai/docs/CONSENT-LIVE-CHECK.md>)
- **Assessment.** Site readiness, particularly content quality or depth, is the leading working hypothesis from the onboarding label and email tip. Labormin has a documented review request. The generic notice provides no equivalent evidence about a GoatLab decision. Duplicate accounts and payment or identity checks are documented alternatives, with no corresponding prompt observed in the available account view.

## How to read AdSense statuses

| Signal in AdSense | How to interpret it |
| --- | --- |
| Payments task or identity verification prompt | Complete the specific account task. An outstanding task can delay site review. [Site statuses](https://support.google.com/adsense/answer/12170222?hl=en), [Account setup](https://support.google.com/adsense/answer/7402256?linkId=17443183) |
| Explicit duplicate message or a known existing AdSense account | Confirm the existing account and payee first. Use the existing account if it is the one the publisher intends to keep. [Account disapproval](https://support.google.com/adsense/answer/81904?hl=en), [Multiple accounts](https://support.google.com/adsense/answer/9729?hl=en) |
| Verification or access error on a named site | Check the URL, selected ownership method, publisher ID, public HTML and crawl access for that domain. [Connect your site](https://support.google.com/adsense/answer/7584263?hl=en), [Site troubleshooting](https://support.google.com/adsense/answer/12176698?hl=en) |
| A domain shows “Needs attention” | Open that row for its details. This is a site-level decision. [Site statuses](https://support.google.com/adsense/answer/12170222?hl=en) |
| A domain shows “Getting ready” | Review is in progress or waiting for account setup. Google says reviews usually take a few days and can take two to four weeks. Removing a site during review can delay it. [Site statuses](https://support.google.com/adsense/answer/12170222?hl=en) |
| Only an ads.txt status appears | Treat it as a separate field. “Authorized” verifies the seller entry and a site still needs a “Ready” approval status before it can serve ads. [Site statuses](https://support.google.com/adsense/answer/12170222?hl=en), [Ads.txt guide](https://support.google.com/adsense/answer/12171612?hl=en) |

The Policy center covers issues affecting ad serving. A missing or empty Policy center gives little information about a stalled initial activation. If onboarding still hides the domain and reason, Google's signed-in account help and Contact Us flow can show the available support options. The useful request is for the URL currently tied to onboarding and the specific task or policy category preventing approval. [Policy center overview](https://support.google.com/adsense/answer/9485926?hl=en), [Policy center FAQ](https://support.google.com/adsense/answer/11071207?hl=en), [Your AdSense account page](https://support.google.com/adsense/answer/16344200?hl=en), [Support options](https://support.google.com/adsense/answer/2581949?hl=en)

## Account and payments checks

- Google allows one AdSense account per publisher and supports multiple sites in that account. Search prior Google logins and past AdSense, AdSense for YouTube, Blogger or AdMob registrations if there is a credible duplicate lead. The disapproval email may identify the other account. An existing AdSense for YouTube account can be expanded for web AdSense under the same account number and payee. Google documents a separate account option for a registered organization distinct from the individual publisher, with the corresponding account and payee information. [Account disapproval](https://support.google.com/adsense/answer/81904?hl=en), [Multiple accounts](https://support.google.com/adsense/answer/9729?hl=en), [YouTube account upgrade](https://support.google.com/adsense/answer/9247020?hl=en), [AdMob account upgrade](https://support.google.com/adsense/answer/6023158?hl=en)
- Check the Payments card for correct account type, full legal payee name, country, deliverable address and phone if prompted. Google's current setup guide says that starting June 2026, some publishers may be asked for government-issued ID before activation and have 45 days after the first request before activation is paused. The address PIN and payout method have separate earnings thresholds. The account's actual prompts determine which verification steps apply. [Payments information](https://support.google.com/adsense/answer/47333?hl=en), [Account setup](https://support.google.com/adsense/answer/7402256?linkId=17443183), [Payment thresholds](https://support.google.com/adsense/answer/1709871?hl=en)
- Peru is on the AdSense availability list, and Latin American Spanish is a supported primary language. The published eligibility guidance gives qualitative criteria around original content, audience and usability. It gives no numerical page, word or visitor threshold. [AdSense availability](https://support.google.com/adsense/answer/13402307?hl=en), [Supported languages](https://support.google.com/adsense/answer/9727?hl=en), [Eligibility requirements](https://support.google.com/adsense/answer/9724?hl=en), [Page readiness](https://support.google.com/adsense/answer/7299563?hl=en)

## Site verification and consent

- Use the verification option shown for the selected domain. Google documents the AdSense loader in the HTML head, a root ads.txt entry, and an AdSense account meta tag in the HTML head. It also documents ownership detection through Search Console in its site troubleshooting guidance. Match the chosen method to the publisher ID in the signed-in account. The same public ID on two domains is consistent with one publisher monetizing multiple properties. [Connect your site](https://support.google.com/adsense/answer/7584263?hl=en), [Site troubleshooting](https://support.google.com/adsense/answer/12176698?hl=en), [Multiple accounts](https://support.google.com/adsense/answer/9729?hl=en)
- Google recommends ads.txt, and it is required for the ads.txt verification method. An existing ads.txt file with the wrong publisher entry can block that seller's ad requests. The file should be reachable from the apex over HTTP and HTTPS, with a supported redirect if applicable and a final 200 response. [Ads.txt guide](https://support.google.com/adsense/answer/12171612?hl=en), [Ads.txt crawl checks](https://support.google.com/adsense/answer/7679060?hl=en), [Ads.txt FAQ](https://support.google.com/adsense/answer/9785052?hl=en)
- For site access, check the submitted URL, certificate, HTTP-to-HTTPS redirect, canonical host, robots rules, authentication and any CDN or firewall challenges. Google identifies `Google-Display-Ads-Bot` as its site verification crawler and `Mediapartners-Google` as its AdSense content crawler. Search indexing and crawler-user-agent probes are indirect evidence. Server or CDN logs can verify a real Google request through Google's published IP ranges or reverse and forward DNS. [Site troubleshooting](https://support.google.com/adsense/answer/12176698?hl=en), [AdSense crawlers](https://support.google.com/adsense/answer/99376?hl=en), [Verify Google requests](https://developers.google.com/crawling/docs/crawlers-fetchers/verify-google-requests)
- A publisher privacy policy must disclose data collection, sharing and use resulting from Google's products, including the identifiers involved and how third parties can collect them through ad serving. Google describes CMP selection as optional when requesting a site review. A Google-certified CMP with IAB TCF integration is required for personalized ads in the EEA, UK and Switzerland. Check that requirement separately from approval and follow Google's disclosure and consent rules where applicable. [Publisher privacy disclosures](https://support.google.com/publisherpolicies/answer/10502938?hl=en#privacy), [Connect your site](https://support.google.com/adsense/answer/7584263?hl=en), [Consent management requirements](https://support.google.com/adsense/answer/13554116?hl=en)

## Editorial review criteria

Google reviews the entire site for useful original content and straightforward navigation. Its inventory policies prohibit ads on pages with little or no publisher content, under-construction pages, and pages with embedded or copied material where the publisher contributes too little commentary, curation or other value. The examples cover automatic generation without manual review, republishing, and lightly rewriting other sources. Attribution and permission are separate from whether the site adds value. Licensed material still needs an original contribution, and that contribution does not itself confer permission to use other parties' media. [Account disapproval](https://support.google.com/adsense/answer/81904?hl=en), [Page readiness](https://support.google.com/adsense/answer/7299563?hl=en), [Low-value inventory](https://support.google.com/publisherpolicies/answer/11112688?hl=en), [Replicated content](https://support.google.com/publisherpolicies/answer/11190248?hl=en), [Intellectual property abuse](https://support.google.com/publisherpolicies/answer/10402772?hl=en)

- For Labormin, review the job details as a visitor who already has the source vacancy open. The site's selection for Peruvian applicants, checking availability and links, identifying location and language requirements, distinguishing documented sponsorship from an unknown status, and explaining how to apply can give readers material they cannot get from a copied listing. Visa guidance and salary claims benefit from dated official references and clear limits on what a source establishes. This is an application of Google's quality criteria to the site's editorial model. [Labormin](https://labormin.com/), [Replicated content](https://support.google.com/publisherpolicies/answer/11190248?hl=en)
- For GoatLab, distinguish the original model, interpretations and tactical commentary from fixtures, scores, lineups, logos and other sourced inputs. A match page is stronger where it interprets what the numbers mean for that specific match and marks preview, projection and post-match fact separately. The gambling restriction focuses on facilitating real-money gambling and includes affiliates that promote it. Editorial match analysis and a probability model warrant a different assessment from bookmaker links, promotions or mechanisms for wagering. Review rights to any third-party media separately. [GoatLab](https://goatlab.win/), [Replicated content](https://support.google.com/publisherpolicies/answer/11190248?hl=en), [Online gambling restriction](https://support.google.com/publisherpolicies/answer/10437963?hl=en), [Intellectual property abuse](https://support.google.com/publisherpolicies/answer/10402772?hl=en)

## Baseline production checks on November 7

| Check | Labormin | GoatLab |
| --- | --- | --- |
| Canonical HTTPS homepage | HTTP 200 | HTTP 200 |
| Verification in original HTML | Matching `google-adsense-account` meta tag. The regular ad loader is paused. | Matching AdSense loader in the document head and a Funding Choices tag |
| Root `ads.txt` | HTTP 200, plain text and a Google DIRECT entry for the signed-in publisher | Same |
| `robots.txt` and declared sitemap | HTTP 200, wildcard allow and reachable `sitemap-index.xml` | Same |
| Canonical plain-HTTP homepage | HTTP 200, no redirect to HTTPS | HTTP 200, no redirect to HTTPS |
| HTTPS `www` alias | DNS lookup failed | HTTP 404 |

Both canonical homepages returned 200 with default, `Googlebot`, `Google-Display-Ads-Bot` and `Mediapartners-Google` user agents. The HTML, robots and ads.txt responses give no evidence of a current canonical-host block or ID mismatch. These probes came from our network. Actual Google access at the time of the review would require authenticated crawler logs. The method selected in AdSense was unavailable in the signed-in view. The ads.txt file also returned 200 over plain HTTP on both apex hosts. [Labormin ads.txt](https://labormin.com/ads.txt), [GoatLab ads.txt](https://goatlab.win/ads.txt), [AdSense crawler documentation](https://support.google.com/adsense/answer/99376?hl=en)

The absent HTTP-to-HTTPS redirect is a reproducible deployment gap in both sites. Google's site readiness checklist explicitly calls for the redirect when HTTPS is used. The apex HTTPS URLs already work, so this alone cannot explain the decision. Route each apex HTTP request to its HTTPS equivalent at the Cloudflare edge and preserve the path and query string. Verify any proposed zone-wide change against subdomain usage, or scope the rule to the apex. The `www` gap is relevant if that host was submitted, previously published, or linked. In that case, add DNS and redirect it to the apex, then verify both HTTP and HTTPS. [Google site readiness checklist](https://support.google.com/adsense/answer/12176698?hl=en), [Cloudflare HTTPS enforcement](https://developers.cloudflare.com/ssl/edge-certificates/encrypt-visitor-traffic/), [Cloudflare www redirection](https://developers.cloudflare.com/pages/how-to/www-redirect/)

To reproduce the main public checks:

```sh
for domain in labormin.com goatlab.win; do
  curl -sS -D - -o /dev/null "http://$domain/"
  curl -fsS "https://$domain/ads.txt"
  curl -fsS "https://$domain/robots.txt"
  curl -fsS "https://$domain/sitemap-index.xml"
  curl -sS -A 'Google-Display-Ads-Bot' -o /dev/null \
    -w '%{http_code}\n' "https://$domain/"
done
```
