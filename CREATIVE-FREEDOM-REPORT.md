# Libertad creativa y límites del flujo de video

**Actualización:** la revisión ahora es orientativa (hasta ocho imágenes) y no veta entregas ni dispara renders. Autoría, reparación y revisión usan max; hay una corrección técnica. Remotion pasa a 4.0.537. El [informe de optimización](VIDEO-OPTIMIZATION-REPORT.md) describe el contrato vigente y la alternativa de revisión manual.

**Registro histórico:** las secciones siguientes documentan la primera implementación y sus pruebas, antes de esta optimización; sus cifras de revisión y correcciones ya no son la política vigente.

Implementación del 21 de octubre de 2026. Este reporte describe el camino nuevo de composiciones JSX (plan 5); los planes 1–4 se conservan para compatibilidad manual, no como montaje de respaldo.

## Qué decide OpenClaw

El nivel de libertad es alto para composición y animación 2D programable, dentro de un runtime definido. No es una calificación medida ni una garantía de calidad. Antes escogía familias de gráficos existentes; ahora escribe un módulo React/JSX completo por audio, con helpers propios, SVG, máscaras y estilos. Puede cambiar tipografía, color, tamaño, distribución, densidad, movimientos, transiciones y secuencias; combinar fotos y clips en dos, tres o más regiones; hacer aparecer texto, trazos, tarjetas y gráficos sin fondo; usar todo, parte o nada del inventario. Los efectos del video de referencia son inspiración, no pasos obligatorios.

Las skills oficiales remotion-create y remotion-markup se instalan en el workspace del Gateway, con sus referencias y UPSTREAM.json. Los turnos de autoría reciben ambos SKILL.md precargados, sin depender de que el modelo haga una lectura antes de escribir. Se fijan al commit 039e8a2fc78b67efc228d5645367838b85818a1c, skill 4.0.537, interpretadas para el runtime existente 4.0.533. El contrato de GoatLab adapta la guía interactiva al flujo automático: no abre Studio ni instala dependencias por audio. Se retiró el catálogo artístico del camino principal; no se exige alternancia, porcentaje de motion, frecuencia de cortes ni mínimo de fotos, clips o subtítulos.

OpenClaw elige si incluye subtítulos y cómo se ven, usando los tiempos transcritos. También elige presencia o ausencia de música. La música disponible es la cama existente; la mezcla de voz permanece a cargo de Render. El motor agrega el logo GoatLab durante el último segundo, dentro del total máximo de 55 segundos. La forma, tamaño y fondo de ese cierre son fijos.

DeepSeek deepseek-v4.1-flash es principal y GLM glm-5.3-flash es respaldo, vía OpenCode Go, ambos dentro de OpenClaw. Render conserva Mistral Voxtral y Whisper para transcripción y ejecuta Remotion/FFmpeg sin un modelo creativo. El supervisor mantiene hasta seis conceptos recientes del mismo chat en el estado privado de 24 horas; ayuda a variar, pero no compara automáticamente la similitud visual de videos anteriores ni garantiza que nunca se repitan recursos o estilos.

Se recomienda grabar hasta 50 s. No se modifica el texto hablado. |
| Música | Booleano music, una cama existente, volumen y normalización del mezclador. | No compone música ni escoge otras pistas o efectos sonoros. |
| Herramientas de dibujo | React y una interfaz Remotion con hooks, SVG, CSS y adaptadores locales de imagen/video. | No puede añadir paquetes, plugins, Three.js, Lottie ni fuentes remotas por su cuenta. Puede crear helpers y gráficos originales con estas herramientas. |

## Qué puede impedir entregar un video de menos de 55 segundos

La duración es el único máximo editorial de tiempo. No significa que cualquier archivo corto sea ejecutable o entregable. Estas comprobaciones siguen activas:

1. **Audio y transcripción:** audio con duración finita positiva; presupuesto de velocidad; transcripción no vacía y tiempos válidos dentro de la voz (tolerancia de 0.3 s). Voxtral falla hacia Whisper; si ambos fallan, no se inventa el texto ni se entrega el montaje.
2. **Contrato del código:** plan version:5, code JSX no vacío, máximo 200 KB, módulo con export default y sintaxis válida. Imports de react y de la interfaz permitida de remotion; sin imports dinámicos, reexportaciones, APIs Node, red externa o acceso directo al DOM global. Se declara al menos un intervalo de escena válido para revisión, pero no se exige cantidad, duración artística mínima, alternancia ni cobertura contigua de esa lista. El contenido se dibuja durante contentFrames; el motor reserva el logo.
3. **Compilación y ejecución:** errores JSX/JavaScript, componente no renderizable, recursos inexistentes, expresiones que fallan, animación costosa o esperas interminables pueden fallar antes de producir MP4. El diagnóstico regresa a OpenClaw para corregir. La compilación ocurre en un proceso con entorno reducido y límites; el código generado se empaqueta, no se evalúa/importa en Node. Se ejecuta en Chromium con CSP de red y adaptadores de media limitados a este trabajo. Esto no crea una máquina o contenedor de sistema operativo separado por video y no se presenta como aislamiento invulnerable.
4. **Medios:** archivos que no se descargan o decodifican se omiten del inventario preparado; OpenClaw puede continuar sin ellos. Las fotos se normalizan, sin crear detalle nuevo; límites de descarga 64 MiB por foto y 32 MB por clip; cachés aproximadas de 128 MB por tipo. No hay máximo artístico de duración de clip en Render ni recorte de cantidad de recursos recibidos. Los recursos externos al trabajo no están disponibles para el código de composición.
5. **Solicitud y datos:** Bearer válido; chat e identificadores válidos; variant 0–9; audioFileId válido o audioUrl HTTPS; trabajo no caducado; JSON HTTP hasta 1 MB; assets/clips como listas y procedencia Agnes. Los facts siguen exigiendo datos finitos no negativos, id, label, unit y source, con hasta 128 registros. El texto o número dibujado por JSX libre no se compara automáticamente con ese catálogo: esa comprobación semántica depende de la autoría y revisión de OpenClaw. Motion Prompts son una lista informativa sin cuotas ni familias obligatorias. Una solicitud inválida puede ser rechazada antes del montaje.
6. **MP4 final:** video y audio válidos, formato definido, 30 fps, duración finita ≤55 s y diferencia respecto al presupuesto del trabajo ≤0.1 s; archivo menor de 45 MB. Un video de 40 s con dimensiones incorrectas o un tamaño excesivo puede rechazarse. No hay duración mínima editorial de cinco segundos: sí un número positivo de fotogramas de contenido además del logo y los márgenes de voz. En el camino normal de voz, esos márgenes y el logo hacen que la salida mínima sea aproximadamente 2.03 s.
7. **Dictamen visual:** OpenClaw puede pedir correcciones por texto ilegible, encuadres, superposiciones o incoherencias. Para aprobar deben estar aprobados todos los lotes de fotogramas. Transparencia, diversidad y ritmo son preferencias; no hay umbrales numéricos que los conviertan en cuotas. La calidad sigue siendo una decisión del modelo y puede fallar o ser demasiado conservadora.
8. **Entrega exacta y recuperación:** generación, revisión, hash del plan y hash del MP4 deben coincidir; se exigen recibos de todos los fotogramas y observaciones. Se comprueba de nuevo el hash de los bytes antes de enviar. Un candidato cancelado, cambiado, obsoleto o sin aprobación no se entrega. Un envío incierto de Telegram no se duplica automáticamente. Repeticiones técnicas son idempotentes; solo un reintento explícito cambia el token para iniciar otra generación tras un fallo.
9. **Proveedores y operación:** OpenClaw puede agotar el tiempo de un turno, el modelo puede no devolver JSON/código válido, el proveedor puede fallar o limitar consumo, y Telegram puede rechazar un envío. Existen respaldo GLM, comprobaciones de arranque, persistencia y recuperación; no eliminan esos límites externos.

## Pruebas y despliegue

- Suite general del repositorio: 582 pruebas Node y 103 Python aprobadas; build Astro, sintaxis y sincronización del skill aprobados. Incluye un caso que devuelve un ReferenceError de JSX a OpenClaw y exige nueva captura antes de aprobar. La comprobación HTTP conserva 11 fotos y siete clips sin recortar el inventario.
- Render real: foto y clip en paneles separados con SVG/texto sin panel de fondo; otra composición solo con gráficos, sin media; inspección de ambas y del cierre de un segundo.
- Límite real: MP4 H.264/AAC de exactamente 55.000 s y 1650 fotogramas, con voz sintética de 53 s y música desactivada.
- API real con Telegram simulado: JSX compilado, MP4 de 5 s, nueve fotogramas de revisión, aprobación y entrega de los mismos bytes por hash. La transcripción estaba preparada y el dictamen de esa prueba fue simulado. Los audios reales antiguos no se reenviaron ni se publicaron videos de prueba al usuario.
- DeepSeek nativo: escribió 4848 caracteres de JSX original a través del OpenClaw desplegado. El módulo se validó, compiló y renderizó sin editarlo manualmente, tanto localmente como en la app Render de Fly. Se inspeccionó su composición de tres regiones.
- GLM nativo: una petición compacta produjo 1335 caracteres de JSX original, compilado y renderizado localmente sin edición manual. Otro intento con ambas skills precargadas, después del ajuste de presupuesto, guardó una composición nueva de 1769 caracteres. Esta última falló al renderizar por hooks no importados. Se devolvió el ReferenceError al mismo modelo; GLM corrigió los imports conservando el diseño (1863 caracteres) y ese módulo compiló y renderizó localmente sin edición manual.
- Despliegue en las dos apps Fly existentes, revisión authored-20261021. Render anuncia editPlanVersion:5, authoredCompositions:true, maxSeconds:55 y endcardSeconds:1. Hashes del servidor y compilador remoto coinciden con el código local. Las dos skills están presentes en Gateway. Render conserva Mistral/Whisper y no tiene credenciales creativas.

Las muestras comprueban rutas de autoría, composición y ejecución; la calidad editorial de piezas futuras depende de cada narración y su revisión. La valoración de libertad describe herramientas y decisiones disponibles, no una puntuación artística medida.

## Límite de respuesta observado durante las pruebas

En un intento de GLM con las skills precargadas, OpenCode Go devolvió HTTP 200 y OpenClaw registró stopReason=length, sin payload ni herramientas completadas. Se trató de truncamiento de respuesta antes de guardar código, distinto de un rechazo artístico o por duración. Ahora se configura explícitamente maxTokens:32768 en ambas definiciones de modelo, en lugar de depender de un valor implícito para modelos personalizados. No se cambia reasoning_effort ni se añade un cliente LLM a Render.

El intento posterior con ese presupuesto y ambas skills precargadas sí guardó código. El techo sigue existiendo y puede consumirse entre razonamiento y código. Es un límite solicitado, no gasto obligatorio ni garantía de terminación de cualquier pieza compleja.

Como referencia para elegir ese presupuesto, el [fabricante de GLM-5.3-Flash](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash) publica hasta 128K de salida para el modelo base. Esto no prueba que un intermediario siempre conceda ese máximo. La prueba real anterior confirma que la ruta de OpenCode Go/OpenClaw aceptó la configuración y completó la autoría en ese caso.

Comprobación final: tanto la autoría como la corrección de código se probaron con turnos nativos de OpenClaw. La corrección real de GLM y el caso automatizado de devolución de errores confirman el recorrido previsto de reparación; el dictamen editorial completo con voz de un usuario real no se probó enviando mensajes a Telegram. El control de apagado idle se dejó reanudado tras las pruebas aisladas.
